Executive Summary

Why Engineering Teams Track API Drift

Traditional monitoring catches 500 errors. drift-watch catches 200 OK responses that silently corrupt your application logic.

The Silent 200 OK Problem

AI vendors regularly update API response structures without warning. An endpoint might rename usage.cost to billing.amount or change a string ID to an integer. The API still returns 200 OK, so status-page checks pass, but downstream data silently becomes null.

Structural Dot-Path Hashing

Instead of comparing volatile dynamic values (like response IDs or tokens), drift-watch flattens JSON payloads into exact dot.path: type signatures. This isolates pure structural changes with zero false positives.

Automated CI/CD Gating

Runs on automated schedules via GitHub Actions. If a critical field removal or type change is detected, the engine instantly exits with code 1, blocking deploy pipelines and dispatching Webhook alerts to Discord/Slack.

Production Context

Built for Oximy's 6,500+ API Cost Visibility Problem

The Enterprise Challenge

Oximy (YC W26) tracks enterprise AI adoption across thousands of vendor tools. The promise to enterprises is precise visibility into AI spend and ROI.

Why Standard Monitoring Fails

AI providers change usage reporting schemas silently. If an endpoint drops a usage.cost float or moves it inside a billing dictionary, the API still returns 200 OK. Traditional HTTP monitoring marks it healthy, while internal pipelines report $0.00 spend — corrupting enterprise financial data.

The Solution: drift-watch

drift-watch was built to guarantee zero silent schema mutations. By running shape-hashing diffs on continuous schedules in CI/CD, any broken endpoint is caught before it impacts production data.
