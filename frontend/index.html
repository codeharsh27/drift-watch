Case Study

Originally Built for Oximy's Cost Visibility Problem

Context

Oximy (YC W26) tracks enterprise AI adoption across more than 6,500 tools. The core promise to the enterprise is simple but monumental: exact visibility into AI spend and ROI.

The Problem

Fulfilling that promise requires ingesting data from thousands of different APIs. There is no standard for how AI vendors report usage. One vendor might place cost under a usage.cost float. Another places it in billing. Crucially, vendors change these structures without warning. If an endpoint continues returning a 200 OK but silently drops or renames the cost field, downstream pipelines don't crash — they simply report $0.00 spent. This silent corruption destroys data integrity.

The Mechanism

drift-watch was built to catch exactly this. By recursively flattening the JSON payload into a strict dot-path-to-type map, it creates a structural signature (the "Shape Hash"). On every poll, it diffs the current shape against the expected baseline. If a field like usage.cost is missing, or changes from a float to a string, the engine instantly flags it as a Critical Drift and exits with a non-zero code to gate the CI/CD pipeline.

It's a zero-dependency safeguard against silent schema mutations. See it running live ↑
