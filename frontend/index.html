The Problem

The Problem

When an LLM provider changes a field from `float` to `string`, your JSON parser might not throw an error. It might just return `null`.

The Result: Cost trackers fail, dashboards go blank, and data corrupts silently. Drift-Watch validates the shape of your data to prevent silent failures.

BEFORE — vendor v1
AFTER — silent update

Detection Types

What Gets Flagged & Why

Not every change is dangerous. drift-watch draws a clear line between changes that will break your parsers and changes that are just vendor growth.

🚨 Critical Drift

Fields Removed

A field your parser depends on has disappeared from the vendor response. Even if the field silently becomes null, your cost tracking returns zero — and no exception is raised anywhere in the stack.

usage.cost_usd → gone
🚨 Critical Drift

Type Changed

The field still exists, but its type flipped. A float becoming a string passes your null check and truthy check — but breaks every arithmetic operation silently. "0.004" + 0.001 is "0.0040.001" in many languages.

cost: 0.004  →  cost: "0.004"
ℹ️ Informational

Fields Added

New fields appeared in the vendor response. Your existing parsers still function correctly — this is vendor growth, not breakage. drift-watch tracks it for awareness but does not flag it as critical and does not exit non-zero.

billing.cost → new (non-breaking)
