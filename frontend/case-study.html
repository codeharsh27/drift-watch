Engineering for the Unknown: Solving the Silent Null Catastrophe

How we built Drift-Watch to secure data integrity across 6,500+ unstandardized AI vendor APIs.

The Oximy Challenge

Oximy (YC W26) tracks enterprise AI adoption across more than 6,500 tools. The core promise to the enterprise is simple but monumental: We give you exact visibility into your AI spend and ROI.

But under the hood, fulfilling that promise requires ingesting data from thousands of different APIs. There is no standard for how AI vendors report usage. Groq puts tokens in one place. Cohere calls them something else. Gemini nests them three levels deep. And crucially, they change these structures without warning.

The Nightmare Scenario: The Silent Null

If a vendor's API goes down and returns a 500 Internal Server Error, that's actually a good day. Your monitoring tools spike, PagerDuty wakes up the on-call engineer, and you fail over to a backup.

The real nightmare is when the API doesn't go down.

Imagine it's a Friday afternoon. A major LLM provider silently ships a minor update to their response payload. They decide to move their cost metric from usage.cost (a float) to billing.cost_str (a string). They don't bump their API version. They don't send an email.

The HTTP response is a perfect 200 OK.

Because your data pipeline is aggressively pulling this data, your JSON parser reaches for usage.cost. It's missing, so it quietly evaluates to null or falls back to 0.00. No exceptions are raised. No alarms go off.

Over the weekend, your enterprise customer burns through 40,000 queries. On Monday morning, they log into the Oximy dashboard and see their weekend spend was exactly $0.00.

They notice the corrupted data before you do. In B2B SaaS, this is catastrophic. Trust is broken. This is the Silent Null Catastrophe.

The Failed Alternatives

When I first approached this problem, I looked at standard validation libraries like Pydantic or JSONSchema. But at Oximy's scale, traditional validation breaks down:

  • Maintenance Hell: Writing and maintaining strict type models for 6,500+ undocumented, rapidly pivoting AI tools requires an army of engineers.
  • Brittle Validations: Standard schemas often throw fatal errors if a vendor simply adds a new, harmless field (like a new latency_ms metric). We didn't want to break the pipeline for safe additions.

We needed a way to detect structural drift without writing thousands of manual schemas.

The "Aha" Moment: Shape Hashing

Instead of manually typing out rigid models, I built Drift-Watch around a concept I call Shape Hashing.

The premise is simple: What if we could capture the "shape" of a known good JSON response and use it as a fingerprint?

The core engine is a pure-Python, zero-dependency algorithm that recursively walks any JSON tree and flattens it into a map of dot-paths to primitive types.

For example, this payload:

{
  "id": "req_123",
  "usage": {
    "cost": 0.05
  }
}

Is instantly flattened by the engine into a shape map:

  • id: <class 'str'>
  • usage: <class 'dict'>
  • usage.cost: <class 'float'>

When a new payload arrives in production, the engine flattens it the exact same way. It then runs a fast set-difference operation between the expected shape map and the current shape map.

Grading the Drift

Because we use set logic on the flattened paths, the engine can elegantly classify changes without getting confused:

  • Critical Drift (Exit Code 1): A path completely disappeared (e.g., usage.cost is gone), or a type flipped (e.g., usage.cost went from float to str). This immediately halts the CI/CD pipeline, preventing bad parsers from deploying.
  • Informational Drift (Exit Code 0): A new path appeared (e.g., usage.latency_ms was added). The system logs it as a "harmless addition" and lets it pass.

The Result: Bulletproof AI Visibility

By wrapping this core engine in a fast REST API (FastAPI) and a sleek, interactive frontend, Drift-Watch allows engineers to visualize schema changes in real-time.

But more importantly, by running the core differ.py script as a daily cron job against vendor baseline fixtures, Oximy can detect the Silent Null Catastrophe on Day 0.

When a vendor breaks their implicit contract, Drift-Watch catches the drift, alerts the team, and blocks deployments until the parsers are updated. It ensures that when Oximy tells an enterprise they spent $10,000, that number is mathematically, structurally guaranteed to be true.
